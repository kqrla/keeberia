# v1 — micropad mvp (status: next)

> the "someone actually orders a board" version. the lovable frontend talks to the real engine through xano. press button, get gerbers, get a 3d-printable case, send it to jlc.

## the flow

1. user designs a micropad on layout-to-device.lovable.app (grid, keys, knob, oled, switch mount)
2. frontend posts the keeberia layout json to the xano endpoint
3. xano validates → queues a job → the **autolayout daemon** runs the pcb engine and stores the artifacts
4. user gets back: board preview image, drc report, bom, kicad bundle, gerbers, and a printable case (stl)

## backend work

- **engine api on xano** — endpoint `POST /generate` (layout json in, job id out), `GET /job/:id` (status + artifact urls). engine ships as a bundled esbuild module (custom code or self-hosted via aws if bundle limits bite)
- **autolayout daemon** (`backend/daemons/autolayout/`) — the queue worker: claim job → run engine → if routing fails, retry with adjusted parameters (coarser grid → higher congestion budget → relaxed clearance) → persist artifacts → done. runs anywhere with node; targets aws (user has it) or a xano background task if it fits the timeout budget
- **drc + export hardening** — gerber export (x2 + job file) and excellon drills, not just kicad_pcb. jlc-orderable output is the bar
- **case generator** — flow four, openscad programmatic like makerworld makerlab configurators: read the board outline + part heights from the engine output, generate a sandwich case (top plate with key/encoder/oled cutouts, spacer, base with usb port + m2 bosses), export stl + step
- **firmware handoff** — generate a config for a known firmware (kmk/vial) from the same netlist the board came from: matrix map, encoder pins, oled i2c. the layout the user designed should *just work* when the board arrives

## frontend work (lovable)

- wire pcb flow to the real api: job status, live-ish progress, result viewer (svg → gerber viewer later)
- keep the design language: notion/figma/canva vibes. no kicad/eda vibes, ever. routing happens, but hidden — user sees a clean board, never a ratsnest

## definition of done

- [ ] one person (me) orders a v1 board from the frontend and it works when it arrives
- [ ] p95 job time under 30s for a 9-key + encoder + oled board
- [ ] routing success ≥ 99% on valid layouts, with graceful, user-readable errors on the rest
- [ ] case stl prints on an a1 mini without supports
- [ ] zero ai in the copper path (still)
