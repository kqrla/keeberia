# v0 — prototype (status: done)

> the "prove it's possible" version. deterministic engine, verified footprints, boards that pass drc and parse in kicad 8. no api, no daemon, no case. pure command-line proof.

## what's in

- **pcb-engine** (`backend/engines/pcb/pcb-engine/`) — typescript, zero runtime deps
  - layout normalization: grid cells → components, spacers/blockers respected
  - placement: key field on grid, xiao mcu on the back below the keys, m2 holes at corners, outline = bounding box over all part courtyards
  - netlist synthesis: **direct-gpio** when keys fit the pin budget, automatic **diode matrix** fallback (rows × cols, sod-123 on the back) when they don't. i2c hard-reserved for the oled. encoder pins budgeted.
  - routing: fan-out stubs + negotiated-congestion a* on a 0.5mm grid, keepout circles per pad, via costs, per-net rip-up retries with inflating congestion penalties
  - outputs: kicad 8 `.kicad_pcb` (s-expressions), drc report, bom csv, svg preview
- **verified footprints** with per-part provenance notes (`backend/engines/pcb/research/`): mx solder, mx hotswap, ec11, xiao carrier, ssd1306 0.91"/1.3", sod-123, m2 hole, sk6812mini-e (unused in v0)

## validated on

| board | size | mode | nets routed | drc |
|---|---|---|---|---|
| hackpad-3key | 58.3 × 43.0 mm | direct gpio | 5/5 | 0 errors |
| ninepad | 60.3 × 82.0 mm | direct gpio | 12/12 | 0 errors |
| streamdeck | 89.8 × 92.5 mm | matrix (diodes) + encoder + oled | 23/23 | 0 errors |

## explicitly out

- no http api. input is a typescript layout object, output is files on disk.
- no case, no caps, no firmware.
- no persistence — same input, same board, nothing stored.

## definition of done (all met)

- [x] all three test boards route 100% of nets with zero drc errors
- [x] exports open in kicad 8 with correct net numbers, pad geometry, edge cuts
- [x] deterministic: identical input → byte-identical output
- [x] every footprint value traceable to a source (datasheet / kicad official / hackpad care package)
