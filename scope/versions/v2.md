# v2 — keebs later (status: someday, after v1 ships and someone holds a v1 board)

> the "stop calling it a macropad" version. everything learned on micropads, stretched to real keyboards — plus the fun stuff per-key rgb, splits, bigger brains.

## keebs

- **matrix sizes that matter** — 40%→65%, which means the diode matrix is the default, not the fallback. negotiated-congestion routing gets a workout: think 60+ diodes on the back lane
- **stabilizers** — 2u keys in the layout format, stab cutouts in the plate/case generator. the engine's grid stops being uniform and that's fine, cells already carry span
- **choc v1 properly** — low-profile boards: choc footprints verified to the same three-source standard as mx was in v0, plus choc spacing (18×18 / 17×18) and choc stems for caps
- **mcu options** — rp2040-pico class (26 gpio) alongside the xiao for bigger matrices; engine already reserves the option. maybe an rp2040 minimal smd board of our own later

## the fun stuff

- **per-key rgb** — sk6812mini-e is already in the verified footprint set from v0; v2 adds the chain to the netlist (data in → daisychain → data out) and the firmware config
- **split boards** — two halves, trrs/jack between them, one engine run producing two coordinated boards + interconnect netlist
- **encoders everywhere** — knobs in keeb positions, not just micropad corners
- **bom + pick-and-place** — jlc assembly-ready cpl files so the rgb boards can actually be assembled, not just fabricated

## hard nos (carried from v1)

- ai in the copper path. it stays deterministic, forever
- exposing eda concepts to users. logical objects only
